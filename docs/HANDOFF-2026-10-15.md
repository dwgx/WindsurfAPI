## 1. 接手三分钟内会踩的（只写 09-17-B 之后的变化；旧 5 条仍有效）

1. 分支 → 独立评审 → `git merge --ff-only` → push。**不要直接在 `master` 上 commit**。
2. **`runtime-config.json` 是本机操作员文件**（gitignore 的活配置；`src/runtime-config.js:18` 从
   `config.dataDir` 解析）。两条 2026-10-15 实测：
   - **文件里的 pin 会盖过 env**：`quota.spendOnDemand:false` 让 `test/devin-connect-breaker.test.js`
     的 6 个用例在**裸 `node --test`** 下失败（43 pass / 6 fail）。走 `test/setup-env.mjs` 的
     `npm test` 路径时 DATA_DIR 被改到临时目录、pin 读不到 → 49/49 全绿。**这是测试隔离缺陷，
     不是产品缺陷**（它只会更红，不会更绿）。
   - **裸 `node --test` 会改写操作员文件**：`test/breaker-tunable-hotswap.test.js`（12 测试，
     `_resetRuntimeConfigForTests` + 15 次 `setBreakerTunables`）裸跑一次，盘上
     `quota.spendOnDemand: false → null`、`breaker.errorStreakThreshold: null → 2`。
     `persist()` 写整个 `_state`，而 `DEFAULTS.credentials` 是空串 —— **真部署上等于把面板口令
     哈希与 API key 抹成空**。走 `npm test` / `npm run test:release`（都 preload `setup-env.mjs`）
     不会碰到操作员文件。
     **规则：跑单个文件也用 `node --import ./test/setup-env.mjs --test <file>`，并在跑测试前后
     备份 `runtime-config.json`。**
   - 给 breaker 套件加 `beforeEach(_resetRuntimeConfigForTests())` 的候选修复（九兄弟套件的做法）
     **已实测、未采纳**：裸跑确实变绿（49/49），但它把 reset 后的默认状态经后续 setter 落盘 ——
     把「裸跑 6 红」换成「裸跑抹掉操作员配置」，更坏。两份对照文件在 `.agent/gap-20261015/`。
     （九个 reset 套件里有 **4 个**同时调会落盘的 setter：`backend-switch-hotswap`(24)、
     `breaker-tunable-hotswap`(15)、`quota-tunable-hotswap`(13)、`runtime-config-hardening`(9)；
     四个文件的头注释都写明「隔离依赖 setup-env 的临时 DATA_DIR」。裸跑它们同样会改写操作员文件，
     已实测两个：breaker-tunable-hotswap 与 quota-tunable-hotswap。）
3. `npm run mutate` 需要**受信 POSIX git**（`scripts/mutation-harness-utils.mjs:11-19` 的候选表是
   Unix 绝对路径）：Windows 上跑不了，突变判决去 WSL/Linux bench 做。Windows 门需要
   `GATE_INERT_SKIP_PATHS` 声明（**4 条**，语义与完整清单见 CONTRIBUTING 的对应小节与 `.env.example`），Linux CI 不需要。
4. **PR 门禁工具在 `.claude/scripts/`**（`pr-gate.mjs` / `triage.mjs`，gitignore 的本机控制面）：
   它自带一个隔离 worktree 跑机械门。2026-10-05 之前它对「有 suite 见证的 0 测试行」会误判为说谎并

## 7. 反省：这个仓库反复出现的失败形状

1. **数字写在不是它权威来源的地方就会烂**（仓库自己写的规矩）。上面 6.1 表就是它最新的
   收据：spec 数在三个文件里各写一个值，轮数在三个文件里停在上上轮。**数字只写在能重测它的地方**，
   其它地方链接过去。
2. **板子快照会伪装成现状**。活板（`.agent/`）不是 git 的一部分，且它的「快照」段隔一天就成了错的
   （「落后 4 个提交、3 项脏」→ 实际 7 个、1 项）。**每条状态必须带日期与它测的是哪个 SHA**，
   接手时先重测再引用。
3. **门禁看不见的东西比看得见的多**：套件不跑突变 spec；突变 anchor 会被别人的合并杀死；丢图能通过
   wire 字节相等；PR 的 CI 可以一次都没跑（`action_required`）而 GitHub 只显示一个灰色圆点。
   **「绿」的含义永远要问一句：哪个门、在哪棵树上、测了什么。**
4. **本地证据（200MB+）不在 git 里**——一次误删就没有了。重要的结论必须同时落进 `docs/`。
5. **首次贡献者的 PR 卡在 CI 批准上**：#279/#280 自 10-08 起零 review 零 CI。维护者侧的第一动作是
   **批准 workflow 运行**，否则后面所有「对着证据评」都无从谈起。
