      实验性功能

      尚未稳定的优化项；如果发现异常可以随时关闭
      Cascade 对话复用
      多轮对话时复用同一个 cascade_id，只把最新一条 user 消息发给 Windsurf，让服务端维持上下文缓存。命中时可显著降低 TTFB 与上传体积；未命中或账号/LS 变更会自动回退到新会话。需要客户端保留完整历史并按顺序追加（如 new-api、OpenWebUI）。
      启用 Cascade 对话复用
      默认开启。关闭后当前对话池立即停止复用。
      配额低水位时屏蔽 premium 模型
      所有账号本周配额都低于 5% 时，对 premium 模型（claude-opus / claude-sonnet 等）请求直接返 503，避免上游 rate-limit 烧最后一点配额。免费层模型（gemini-2.5-flash 等）保持可用。关闭后即使在 drought mode 也照常下发，accept 上游可能立即 429。
      启用 drought-mode premium 屏蔽
      默认开启。drought 状态由账号池自动判定（GET /dashboard/api/drought 看实时值）。
      账号本周配额低于此值即计入 drought
      粘性会话按用户绑定
      开启后，同一 user 无论请求什么模型都会固定绑定到同一个上游账号。关闭时按 (user, model) 二元组分别绑定（不同模型可能分配不同账号，适合账号有模型限制的场景）。需启用 STICKY_SESSION_ENABLED=1 才生效。
      忽略模型维度
      默认关闭。开启后 user_a 下的 opus/haiku/gemini 全部共享同一个绑定。
      粘性会话禁止回退
      开启后，粘性会话绑定的账号如果遇到限流/错误/模型不可用，不会自动切换到账号池中的其他账号，而是直接将错误返回给客户端。这样可以确保每个 user 严格只消耗自己绑定账号的额度。需启用 STICKY_SESSION_ENABLED=1 才生效。
      禁止账号回退
      默认关闭。开启后绑定账号失败时不会切换到其他账号消耗额度。
      原生 tool_call
      开启后工具定义走原生 protobuf 线协议（已标定的 #10 ToolDef + #6 ChatToolCall），而非提示词模拟（ 文本标记）。原生路对弱模型（fable）多工具更稳、不受提示词模拟的空回复限制。关闭则回退到提示词模拟（当前默认稳定路径）。
      启用原生 tool_call
      默认开启（runtime-config.js 的 experimental.nativeToolCall）。关闭则回退到提示词模拟。
      Cline 兼容模式
      Cline 兼容 ON
      为 Cline 插件做原生级兼容。Cline 的 OpenAI Compatible provider 底层是 @ai-sdk/openai-compatible，对 tool_call 的 arguments 有 isParsableJson 门槛——参数串不是合法 JSON 就静默丢弃这次工具调用（Claude 对无参数工具会发空串）。开启后，识别为 Cline 的请求（按 User-Agent）在标准 /v1 端点会自动套用兼容垫片（tool_call 参数归一为合法 JSON）。专用端点 /v1/cline/*（如 /v1/cline/chat/completions）无论此开关是否开启都始终生效——命名空间本身就是显式选择。默认关闭，标准 /v1 对其他客户端保持字节等价。
      启用 Cline 特征识别兼容
      默认关闭。开启后按 User-Agent 识别 Cline 请求自动套兼容层；/v1/cline/* 专用端点不受此开关约束。
      已修复 tool_call 参数次数 0 （把空/坏 JSON 参数归一为 {} 的累计次数，防 @ai-sdk 静默丢工具）
      Claude Code 兼容
      已启用
      为 Claude Code 做原生级兼容。检测激活后，识别为 Claude Code 的请求会自动套用兼容层：剥离顶层 schema combinator（anyOf/oneOf/allOf）并把竞品身份行中和，避开上游 content-policy 拦截。专用端点 /v1/cc/*（如 /v1/cc/messages）无论此开关是否开启都始终生效——命名空间本身就是显式选择。默认关闭，标准端点对其他客户端保持字节等价。
      启用 Claude Code 特征识别兼容
      默认关闭。开启后按检测特征识别 Claude Code 请求自动套兼容层；/v1/cc/* 专用端点不受此开关约束。
      Schema 规范化 0 （剥离顶层 combinator 的累计次数）
      身份中和 0 （中和竞品身份行的累计次数）
      发送前预检配额
      每次 chat 前先探一次 server.codeium.com 剩余配额,无额度账号直接快速失败,避免烧上游 429。代价是每请求多一次网络往返。
      启用发送前预检
      默认关闭。会增加延迟;账号频繁耗尽时再开。
